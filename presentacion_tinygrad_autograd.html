Que es Tinygrad?

~19K Lineas de codigo
65B Parametros (LLaMA)
6+ Backends GPU

Framework de deep learning creado por George Hotz (2020). Demuestra que un motor de redes neuronales completo NO necesita millones de lineas de codigo. Ejecuta modelos de produccion reales: LLaMA-65B, Stable Diffusion, Whisper.

Diferenciacion Automatica

El Problema

Entrenar una red neuronal requiere calcular gradientes de la funcion de perdida respecto a TODOS los parametros.

  • Millones de parametros
  • Funciones muy complejas
  • Necesitamos precision exacta

La Solucion: Autodiff

Usar la regla de la cadena sistematicamente:

dz/dx = dz/dy · dy/dx

Exacto, eficiente, automatico. Una sola pasada backward calcula TODOS los gradientes.

Por que Autodiff?

Alternativas

  • Simbolica: Exacta pero las expresiones explotan en tamano
  • Numerica: Aproximada, O(n) evaluaciones, error de redondeo
  • Automatica: Exacta, O(1) respecto al forward, eficiente

Reverse Mode (Backprop)

En DL tenemos:

  • Millones de entradas (parametros)
  • UNA salida (loss escalar)
Reverse mode: 1 pasada = TODOS los gradientes

Por eso usamos backpropagation (reverse mode autodiff).

Grafos de Computacion

[x1] ---(*w1)--- [x1w1] ---\ (+) --- [sum] --- (+b) --- [n] --- [tanh] --- [o] [x2] ---(*w2)--- [x2w2] ---/ | [b] DAG: Directed Acyclic Graph (Grafo Dirigido Aciclico)

Cada operacion crea un nodo en el grafo. Los nodos hoja son entradas/parametros. El grafo permite: backpropagation automatica, optimizacion (fusion de kernels), y ejecucion multi-backend.

Backpropagation: Paso a Paso

1

Forward Pass

Ejecutar la red de izquierda a derecha. Cada operacion registra sus dependencias en el grafo.

2

Calcular Loss

Evaluar la funcion de perdida (MSE, Cross-Entropy). Resultado: un escalar.

3

Inicializar Gradiente

El gradiente del loss respecto a si mismo es 1.0. Este es el punto de partida.

4

Backward Pass

Recorrer el grafo en orden topologico INVERSO. En cada nodo: aplicar regla de la cadena.

Gradientes Locales por Operacion

Operacion Forward Backward
c = a + b Suma da = 1*dc, db = 1*dc
c = a * b Producto da = b*dc, db = a*dc
b = relu(a) max(0, a) da = (a>0)*db
b = exp(a) e^a da = exp(a)*db
C = A @ B MatMul dA = dC@B^T, dB = A^T@dC

Cada operacion solo necesita saber su gradiente local. La regla de la cadena encadena todo automaticamente.

Eager vs Lazy Evaluation

Eager (PyTorch)

c = a + b    # Ejecuta AHORA
d = c * 2    # Ejecuta AHORA
e = d.relu() # Ejecuta AHORA

3 kernels separados
3 buffers en memoria GPU
6 accesos a memoria global

Lazy (Tinygrad)

c = a + b    # Solo registra
d = c * 2    # Solo registra
e = d.relu() # Solo registra
e.realize()  # Ejecuta TODO junto

1 kernel fusionado
1 buffer en memoria GPU
2 accesos a memoria global

Fusion de Kernels

Sin Fusion (3 kernels)

Memoria: lee a, b
Kernel 1: c = a + b
Memoria: escribe c, lee c
Kernel 2: d = c * 2
Memoria: escribe d, lee d
Kernel 3: e = relu(d)
Memoria: escribe e

6 accesos a memoria

Con Fusion (1 kernel)

Memoria: lee a, b
Kernel Fusionado:
e = relu((a + b) * 2)

3 operaciones en registros GPU
Sin escrituras intermedias
Memoria: escribe e

2 accesos a memoria (3x menos)

Valor de Negocio

Romper el Lock-in NVIDIA

Mismo codigo para GPUs NVIDIA, AMD, Apple e Intel. Reduce dependencia de CUDA y costos de hardware (H100: $25K-40K c/u).

Edge Deployment

Framework liviano (~19K LOC) ideal para dispositivos embebidos e IoT. Sin dependencias pesadas como LLVM o CUDA toolkit.

Costos de Inference

Fusion automatica reduce accesos a memoria 2-4x. Menos costos de compute en produccion para APIs de LLM.

Auditabilidad

Codigo legible y auditable facilita compliance en industrias reguladas: salud, finanzas, defensa.

Tiny Corp: El Modelo de Negocio

Hardware Chips AI propios optimizados para tinygrad
Cloud Servicio de compute basado en tinygrad
Open Source Framework libre, negocio en HW + servicios

George Hotz fundo tiny corp para comercializar tinygrad. El framework sigue siendo open source; el modelo de negocio se centra en hardware especializado y servicios de cloud compute como alternativa al ecosistema NVIDIA.

# Motor autograd escalar - 100 lineas class Value: def __init__(self, data, _children=(), _op=''): self.data = data self.grad = 0.0 self._backward = lambda: None self._prev = set(_children) def __mul__(self, other): out = Value(self.data * other.data, (self, other), '*') def _backward(): self.grad += other.data * out.grad # d(a*b)/da = b other.grad += self.data * out.grad # d(a*b)/db = a out._backward = _backward return out # Uso: x = Value(3.0); y = Value(4.0) z = x * y # z = 12.0 z.backward() # x.grad = 4.0, y.grad = 3.0

Conclusiones

  • 1. Autograd = Regla de la cadena sistematica. No hay magia: cada operacion define su gradiente local y la cadena los conecta.
  • 2. Grafos de computacion son la base de todo. Permiten backprop automatico, fusion de kernels, y ejecucion multi-backend.
  • 3. Lazy evaluation habilita optimizaciones superiores. Conocer el grafo completo antes de ejecutar permite fusionar operaciones.
  • 4. Tinygrad prueba que menos es mas. ~19K lineas ejecutan LLaMA-65B. La complejidad de PyTorch no es inherente al problema.
  • 5. Valor de negocio claro. Multi-backend rompe el lock-in de NVIDIA; fusion reduce costos de inference.
