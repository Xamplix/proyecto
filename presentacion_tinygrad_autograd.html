El Problema: Como aprende una red neuronal?

Una red neuronal simple

Imagina una red que predice precios de casas:

precio = peso x area + bias

Al inicio, los pesos son aleatorios. La red se equivoca.

Pregunta clave: como sabe la red en que direccion y cuanto cambiar cada peso para equivocarse menos?

La respuesta: GRADIENTES

El gradiente nos dice:

1. Direccion: subir o bajar el peso?
2. Magnitud: cuanto cambiarlo?

Es como una brujula que apunta hacia el error minimo.

peso_nuevo = peso - tasa * gradiente

Pero una red real tiene MILLONES de pesos... como calcular millones de gradientes?

Repaso: Que es una derivada?

Ejemplo con numeros

Funcion: f(x) = x²

Si x = 3, entonces f(3) = 9

La derivada f'(x) = 2x nos dice:
"Si muevo x un poquito, cuanto cambia f?"

f'(3) = 2 × 3 = 6

Significa: si x sube de 3.0 a 3.001,
f sube ~6 veces mas (de 9.0 a 9.006)

Verificacion numerica

# Verificamos con numeros reales: x = 3.0 h = 0.001 # paso muy pequeno f_x = x ** 2 # = 9.000 f_x_h = (x + h) ** 2 # = 9.006001 derivada = (f_x_h - f_x) / h # = (9.006001 - 9.000) / 0.001 # = 6.001 (casi exacto!)

Derivada = pendiente de la funcion en ese punto.

En deep learning, la derivada del loss respecto a un peso nos dice como ajustar ese peso.

La Regla de la Cadena: El Truco Clave

Problema: funciones compuestas

En una red, las funciones estan anidadas: loss = MSE( relu( W2 × relu( W1 × x + b1 ) + b2 ) , y )
Como derivar esta cadena entera respecto a W1?

La Regla de la Cadena

Si z = f(g(x)), entonces: dz/dx = dz/dy × dy/dx

Idea simple: descomponer la derivada de una funcion compuesta en el PRODUCTO de derivadas simples.

Ejemplo con numeros

y = 2x → dy/dx = 2
z = y² → dz/dy = 2y

Si x = 3: y = 6, z = 36

dz/dx = dz/dy × dy/dx
dz/dx = 2×6 × 2 = 24

Verificacion: si x=3.001, z=(2×3.001)²=36.024
(36.024-36)/0.001 = 24 ✔

Autograd: Derivadas Automaticas

La idea genial

En vez de calcular derivadas a mano, cada operacion recuerda como calcular su derivada. Despues, encadenamos todas las derivadas automaticamente. Eso es autograd.

Cada operacion sabe su derivada

# SUMA: c = a + b # dc/da = 1, dc/db = 1 # "El gradiente pasa directo" # MULTIPLICACION: c = a * b # dc/da = b, dc/db = a # "Se intercambian los valores" # RELU: b = max(0, a) # db/da = 1 si a>0, 0 si a<=0 # "Pasa o bloquea el gradiente"

Se encadenan solas

# Solo escribimos el forward: x = Value(3.0) y = Value(4.0) z = x * y + x # z = 3*4 + 3 = 15 # El backward se calcula SOLO: z.backward() # x.grad = 5.0 (y + 1 = 4 + 1) # y.grad = 3.0 (x = 3) # No tuvimos que derivar a mano!

Ejemplo Concreto: Paso a Paso con Numeros

Neurona simple: o = tanh(w×x + b) con w=-3, x=2, b=6.88

FORWARD: calcular valores →

1 w × x = -3 × 2 = -6.00
2 wx + b = -6 + 6.88 = 0.88
3 tanh(0.88) = 0.707

Resultado: la neurona produce 0.707

BACKWARD: calcular gradientes ←

3 do/dn = 1 - tanh² = 1 - 0.5 = 0.50
2 do/db = 0.50 × 1 = 0.50
1 do/dw = 0.50 × x = 0.50 × 2 = 1.00

Gradiente de w = 1.00: "sube w para subir o"

Si el loss dice "o deberia ser mas grande" → el gradiente dice "sube w en 1.00 unidades por cada paso"

Para que sirve el grafo?

1. Forward: seguimos las flechas hacia abajo para calcular el resultado.

2. Backward: seguimos las flechas hacia arriba para calcular gradientes.

3. Optimizacion: el grafo completo permite fusionar operaciones antes de ejecutar.

Analogia: GPS

El grafo es como un GPS: registra cada paso del camino. Cuando necesitas volver (backward), sabes exactamente por donde pasaste.

Backpropagation: El Algoritmo Completo

Los 5 pasos del entrenamiento

1 Forward: correr la red, obtener prediccion
2 Loss: medir que tan lejos esta de la respuesta correcta
3 Backward: calcular gradientes (regla de la cadena)
4 Update: ajustar pesos en direccion opuesta al gradiente
5 Repetir: iterar hasta que el loss sea bajo

Ejemplo numerico: 1 iteracion

# Datos: x=2, y_real=1 # Peso actual: w=0.5 # PASO 1: Forward pred = w * x = 0.5 * 2 = 1.0 # PASO 2: Loss (MSE) loss = (pred - y_real)² = (1.0 - 1.0)² = 0.0 # Perfecto! Pero si w=0.8: pred = 0.8 * 2 = 1.6 loss = (1.6 - 1.0)² = 0.36 # PASO 3: Backward dL/dw = 2*(pred-y)*x = 2*0.6*2 = 2.4 # PASO 4: Update (lr=0.1) w = 0.8 - 0.1 * 2.4 = 0.56 # w bajo de 0.8 a 0.56 (acercandose a 0.5)

Demo: Entrenando una Neurona (3 iteraciones)

Meta: aprender w tal que w × 2 = 4 (w ideal = 2.0). Empezamos con w = 0.5

Iteracion 1: w = 0.5

pred = 0.5 × 2 = 1.0
loss = (1.0 - 4)² = 9.0
grad = 2(1-4)×2 = -12.0
w = 0.5 - 0.1×(-12)
w = 1.7

Loss alto, paso grande

Iteracion 2: w = 1.7

pred = 1.7 × 2 = 3.4
loss = (3.4 - 4)² = 0.36
grad = 2(3.4-4)×2 = -2.4
w = 1.7 - 0.1×(-2.4)
w = 1.94

Loss bajo, paso pequeno

Iteracion 3: w = 1.94

pred = 1.94 × 2 = 3.88
loss = (3.88 - 4)² = 0.014
grad = 2(3.88-4)×2 = -0.48
w = 1.94 - 0.1×(-0.48)
w = 1.988

Casi perfecto! w ≈ 2.0

w: 0.50 → 1.70 → 1.94 → 1.988 → ... → 2.000     Loss: 9.0 → 0.36 → 0.014 → ~0

El Codigo: Motor Autograd en 30 Lineas

class Value: def __init__(self, data): self.data = data self.grad = 0.0 # gradiente self._backward = lambda: None self._prev = set() # padres def __mul__(self, other): out = Value(self.data * other.data) out._prev = {self, other} def _backward(): self.grad += other.data * out.grad other.grad += self.data * out.grad out._backward = _backward return out def __add__(self, other): out = Value(self.data + other.data) out._prev = {self, other} def _backward(): self.grad += out.grad other.grad += out.grad out._backward = _backward return out def backward(self): self.grad = 1.0 # recorrer grafo en orden inverso for node in reversed(topo_sort(self)): node._backward()

Como funciona?

1 Cada Value guarda su dato y su gradiente.

2 Cada operacion (+, *) crea un nuevo Value y guarda una funcion _backward que sabe calcular el gradiente.

3 Al llamar backward(), se recorre el grafo de atras hacia adelante, llamando cada _backward.

Resultado

a = Value(2.0); b = Value(3.0) c = a * b # c = 6.0 d = c + a # d = 8.0 d.backward() # a.grad = 4.0 (b + 1 = 3 + 1) # b.grad = 2.0 (a = 2)

Arquitectura de Tinygrad

Nuestro autograd opera con escalares. Tinygrad hace lo mismo pero con tensores, GPU y fusion de kernels.

Tensor API (lo que escribe el usuario)

a = Tensor([1,2,3]); c = a + b

↓

UOp Graph (~15 operaciones primitivas)

add, mul, relu, sum, reshape...

↓

Scheduler (fusion de operaciones)

3 ops separadas → 1 kernel fusionado

↓

Codegen (genera codigo para cada GPU)

CUDA | Metal | OpenCL | C | WebGPU

↓

Hardware

NVIDIA | AMD | Apple M1/M2/M3 | CPU

Analogia: Compilador de idiomas

Tu escribes en "Python" (Tensor API).

Tinygrad lo traduce a un "idioma intermedio" (UOps) que entiende de operaciones basicas.

El Scheduler optimiza la traduccion (fusiona frases).

El Codegen lo traduce al "idioma nativo" de tu GPU (CUDA, Metal, etc.).

Dato clave: solo ~15 operaciones

TODA operacion de deep learning (softmax, attention, batch norm) se descompone en ~15 primitivas: add, mul, exp, log, sum, max, reshape, etc.

Eager vs Lazy: Como se ejecutan las operaciones?

Eager (PyTorch): ejecuta al instante

c = a + b # Ejecuta AHORA en GPU # Resultado c va a memoria d = c * 2 # Lee c de memoria, ejecuta # Resultado d va a memoria e = d.relu() # Lee d de memoria, ejecuta # Resultado e va a memoria

3 viajes a memoria GPU:
Escribir c → Leer c → Escribir d → Leer d → Escribir e

Analogia: ir al super 3 veces, una por cada ingrediente

Lazy (Tinygrad): registra y ejecuta todo junto

c = a + b # Solo ANOTA: "sumar a+b" d = c * 2 # Solo ANOTA: "multiplicar por 2" e = d.relu() # Solo ANOTA: "aplicar relu" e.realize() # AHORA ejecuta TODO junto # e = relu((a+b)*2) # UN solo viaje a memoria

1 viaje a memoria GPU:
Lee a,b → calcula todo en registros → Escribe e

Analogia: hacer TODA la lista del super en un solo viaje

Resultado: Lazy puede ser 2-4x mas rapido porque el cuello de botella en GPUs es la MEMORIA, no el computo

Fusion de Kernels: La Magia de Tinygrad

Sin fusion: 3 kernels, 6 accesos a memoria

RAM GPU → Lee a, b
Kernel 1: c = a + b
RAM GPU → Escribe c, Lee c
Kernel 2: d = c * 2
RAM GPU → Escribe d, Lee d
Kernel 3: e = relu(d)
RAM GPU → Escribe e

Con fusion: 1 kernel, 2 accesos a memoria

RAM GPU → Lee a, b
Kernel Fusionado:
e = relu((a + b) * 2)
Todo en registros GPU (ultra rapido)
RAM GPU → Escribe e

Por que importa?

En una GPU, leer/escribir memoria toma ~100x mas tiempo que una operacion matematica. Fusionar = menos viajes = mas velocidad.

Valor de Negocio

1. Romper el monopolio de NVIDIA

PyTorch solo funciona bien con GPUs NVIDIA (CUDA).
Una GPU H100 cuesta $25,000-40,000.

Tinygrad corre el MISMO codigo en NVIDIA, AMD, Apple e Intel. Mas opciones = menores costos.

2. Reducir costos de inference

La fusion automatica de kernels reduce accesos a memoria 2-4x.

Para una empresa que sirve un LLM a millones de usuarios, esto significa miles de dolares ahorrados en compute mensual.

3. Edge Deployment (dispositivos)

Framework de solo ~19K lineas, sin dependencias pesadas.

Ideal para correr modelos en celulares, IoT, robots donde PyTorch es demasiado grande.

4. Auditabilidad y Compliance

En industrias reguladas (salud, finanzas), necesitas explicar tu modelo.

19K lineas legibles vs millones opacas: cual auditas mas facil?

Conclusiones

1. Autograd NO es magia — es la regla de la cadena aplicada automaticamente. Cada operacion guarda como calcular su derivada, y el sistema las encadena.

2. El grafo de computacion es el mapa — registra cada operacion (forward) y permite recorrerlo al reves (backward) para calcular todos los gradientes.

3. Lazy evaluation es clave — al conocer el grafo COMPLETO antes de ejecutar, tinygrad puede fusionar operaciones y reducir accesos a memoria 2-4x.

4. Menos codigo, misma potencia — ~19K lineas ejecutan LLaMA-65B. La complejidad de PyTorch no es inherente al problema.

5. Valor de negocio real — multi-backend rompe el lock-in NVIDIA; fusion reduce costos; auditabilidad facilita compliance.
